## `raises` in a function type

A function type can say what a function of that type raises, as the
function's own first line does: `function(str) -> int raises
ValueError`. A call through such a value is checked as a call of the
function by its name, so its caller catches the error or says
`raises` itself. A function fits the type if `except ValueError` would
catch what it raises, and `raises Error` takes any. A firmware build
and a build with no collector used to refuse `texts.map(parse)` where
`parse` raises; they build it now, and print what `zeno run` prints.
A function that returns a raising function writes that type in
brackets, `-> (function(int) -> int raises ValueError) raises
Missing`, since `raises` after a result has always belonged to the
function it ends. See
[docs/raises-in-types.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/raises-in-types.md)
and chapter 56 of the decisions.

Everything a program wrote for 0.7.0 means what it meant.
