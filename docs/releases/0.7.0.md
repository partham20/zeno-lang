These are the notes of Zeno 0.7.0 as far as it has come. It is not
released: this page is written as the work reaches `main`, and is
finished on the day of the release.

Zeno 0.7.0 takes a program from a `.zeno` file to a chip in one step.
`zeno build --board` runs the board's own compiler, a board can print
and stop by itself with no C library under the program, and a number
with a fraction is made into text by Zeno itself: `primes.zeno`, which
shows one, takes 7,884 bytes of flash on an ARM Cortex-M3. The board
module has the three things it lacked: a PWM signal, a steady beat,
and edges counted by an interrupt.

Everything a program wrote for 0.6.0 means what it meant.

## A PWM signal, a steady beat, and edges

```zeno
from board import pwm_pin, ticker, input_pin, pull_up, falling

let lamp = pwm_pin(9, 1 kHz)
lamp.duty(0.25)                  # on for a quarter of the time

let beat = ticker(10 ms)
let button = input_pin(2, pull_up)
let presses = button.interrupt(falling)

while true {
    beat.wait()                  # the next tick, however long the work took
    if presses.edges() > 0 {
        lamp.duty(1.0)
    }
}
```

- **`pwm_pin(9, 1 kHz)`** gives a `PwmPin`: `duty(0.25)` for a share of
  the time, `pulse(1500 us)` for a servo.
  [docs/pwm.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/pwm.md)
- **`ticker(10 ms)`** gives a `Ticker`: `wait()` waits for the next
  tick and says how many came, so a loop keeps its time and knows when
  it was late.
  [docs/ticker.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/ticker.md)
- **`button.interrupt(falling)`** counts edges in the board's
  interrupt, and the program asks for the count. The program's own
  code never runs inside an interrupt.
  [docs/interrupts.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/interrupts.md)

On a computer the board is simulated, as before.

## One step to a board

```sh
zeno build --board boards/qemu-cortex-m3 blink.zeno
```

A board is a folder. Its `zeno.board` names the compiler, the flags,
the start-up files, the linker script and the command that runs the
result, because those are the board's and not the program's. Zeno
writes the C and types the one long command.

Two boards come with Zeno, and both are one chip that QEMU emulates,
an ARM Cortex-M3 with 256 KB of flash and 64 KB of RAM. Every example
that a build with no collector accepts is built for both and compared
with the same program on a computer. **No program of Zeno's has run on
a real board yet.**
[docs/board-build.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/board-build.md)

## A board that prints and stops by itself

A board's header says `#define ZENO_BOARD_PRINTS` and brings four
functions: for what is printed, what is said beside it, what is typed,
and stopping. Then nothing of the program goes through the C library's
streams or its `exit`. `boards/lm3s6965evb` is written that way, on the
chip's own pin, timer and UART registers, and `hello` takes 932 bytes
of flash there.
[docs/board.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/board.md)

## A float with no C library

`print(x)`, `{x:.2f}` and `float("2.5")` were the C library's
`snprintf` and `strtod`, which are 28 KB of flash on a Cortex-M3. The
runtime now does all three itself, with whole numbers and exactly, in
4 KB.

| program, flash in bytes | `boards/qemu-cortex-m3`, a C library under it | `boards/lm3s6965evb`, the chip's registers |
|---|---|---|
| `hello.zeno` | 9,468 | 932 |
| `primes.zeno` | 16,168 | 7,884 |
| `tour.zeno` | 22,000 | 14,032 |

The first build for a board, with `fprintf` and `snprintf` under the
runtime, made the three 9,772, 38,568 and 50,184 bytes.

On a computer a float is written five to eight times faster, and read
as fast as before.

## A C compiler that is neither GCC nor Clang

The C of a build asked GCC and Clang for a few things by their own
names: whether a sum, a difference or a product overflowed, first of
all. A compiler with none of those names (IAR's, Keil's older one,
tcc) stopped there. Each is now written a second time in plain C, and
a compiler gets the one it can read, with nothing to ask for.

tcc builds every example, and each does what it does built by gcc. On
a Cortex-M3 the plain C is as small as the other. **No program has
been built by IAR's, Keil's or a chip maker's compiler yet.**
[docs/plain-c.md](https://github.com/zeno-src/zeno-lang/blob/main/docs/plain-c.md)

## Mended

- **46 powers of two were printed with 17 digits by a build**, where
  16 name them and `zeno run` printed 16: `2.0 ** -44.0` is
  `5.684341886080802e-14`. The C, the C++ target and the Lua target
  had it.
- **A NaN with decimals**, `f"{x:.2f}"`, was `nan` or `-nan` in a
  build. It is `NaN`, as under `zeno run`.
- **`a * b + c` on floats is two steps for every C compiler.** The
  line that says so was given to gcc and Clang alone. It is now the
  line C itself has for it, for any compiler.
