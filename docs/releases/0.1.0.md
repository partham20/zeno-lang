The first release of Zeno: a small, readable, statically typed language
for firmware and for everything around it. One `zeno` checks a program,
runs it, tests it, formats it, and compiles it to C or to LLVM IR.

Version 0.1 is the whole language as it was set out. What is in it, and
what it leaves out, is in
[docs/version-0.1.md](https://github.com/partham20/zeno-lang/blob/v0.1.0/docs/version-0.1.md).

| Linux, ARM64: a Raspberry Pi 3, 4 or 5 with a 64-bit system, ARM servers | `zeno-0.1.0-linux-arm64.tar.gz` |
| Linux, 32-bit ARMv7: a Raspberry Pi 2 or later with a 32-bit system | `zeno-0.1.0-linux-armv7.tar.gz` |
| Linux, 32-bit ARMv6: a Raspberry Pi 1 or Zero | `zeno-0.1.0-linux-armv6.tar.gz` |

| macOS, Apple silicon | `zeno-0.1.0-macos-arm64.tar.gz` |

Unpack it and put `zeno` (`zeno.exe` on Windows) somewhere on your
`PATH`. It is one file and needs nothing else installed. The folder
also holds the docs, the examples and the editor setup.

```sh
tar -xzf zeno-0.1.0-linux-x86_64.tar.gz
cd zeno-0.1.0-linux-x86_64
./zeno --version
./zeno run examples/hello.zeno
```

On macOS, a program downloaded with a browser is held back because
Apple has not signed it. `xattr -d com.apple.quarantine zeno` lets it
run.

`zeno build` hands the C it writes to a C compiler, so it needs one
(`cc`, or the one `CC` names; on Windows, `set CC=gcc` with MinGW).
`zeno build --llvm` needs clang, and does not work on Windows yet.
`zeno fetch` needs git. Everything else needs nothing.

## What was checked

Every build but one was run before it was released: it ran all the
examples through the interpreter and the virtual machine, ran their
tests, formatted them and made a new program with `zeno new`. The ARM
builds for Linux ran under an emulator and the Intel build for macOS
under Apple's translation. The Windows build for ARM64 was built and
not run, because there was no machine to run it on.

The whole test suite (454 tests), which also compiles every test
program to C and to LLVM IR and runs the result, passes on Linux
x86-64 and on macOS on Apple silicon.

On Windows, `zeno build` with MinGW's gcc was checked on three
examples, which print exactly what `zeno run` prints. `zeno build
--llvm` does not work there yet with the clang that comes with Visual
Studio: the runtime asks for two clock functions that Microsoft's C
library does not have. For the same reason the test suite does not
all pass on Windows: 337 of the 454 tests do, nearly all of the rest
are that LLVM build, and ten compare paths written with `/`.
Compiling with Microsoft's own C compiler (`cl`) has not been tried.
