The first release of Zeno: a small, readable, statically typed language
for firmware and for everything around it. One `zeno` checks a program,
runs it, tests it, formats it, and compiles it to C or to LLVM IR.

Version 0.1 is the whole language as it was set out. What is in it, and
what it leaves out, is in
[docs/version-0.1.md](https://github.com/partham20/zeno-lang/blob/v0.1.0/docs/version-0.1.md).

## Installing

Two installers were added to this release on 16 November 2026. They
install the files of the archives below, which are as they were.

**On Windows**, download `zeno-0.1.0-windows-setup.exe` and run it. It
is the same file for x86-64, 32-bit x86 and ARM64. It installs Zeno
for you alone, with no administrator's password, adds it to the PATH,
and offers to install a C compiler and Git if the machine has none.
The first time, Windows says "Windows protected your PC", because the
program is not signed: "More info", then "Run anyway".

**On macOS and Linux**, one line in a terminal:

```sh
curl -fsSL https://github.com/partham20/zeno-lang/releases/download/v0.1.0/install.sh | sh
```

It works out which archive the machine needs, checks the download
against `SHA256SUMS.txt`, installs into `~/.zeno`, and adds that to
the PATH. `sh install.sh --uninstall` takes it off again.

How both work is in
[docs/install.md](https://github.com/partham20/zeno-lang/blob/main/docs/install.md).

**With a package manager.** Packages were added the same day, made
from the same archives. For apt, pacman, snap and flatpak there is a
file to install:

```sh
sudo apt install ./zeno_0.1.0_amd64.deb                         # Debian, Ubuntu, Raspberry Pi OS
sudo pacman -U zeno-bin-0.1.0-1-x86_64.pkg.tar.zst              # Arch
sudo snap install --classic --dangerous zeno_0.1.0_amd64.snap
flatpak install --user zeno-0.1.0-x86_64.flatpak
```

The `.deb` is also there for `arm64`, `armhf` (every Raspberry Pi with
a 32-bit system) and `i386`, the snap for `arm64` and `armhf`, and the
flatpak for `aarch64`. apt installs a C compiler and git along with
Zeno if the machine has none.

Homebrew, on macOS and Linux:

```sh
brew tap partham20/zeno-lang https://github.com/partham20/zeno-lang
brew install partham20/zeno-lang/zeno
```

For winget there are three files in
[packaging/winget](https://github.com/partham20/zeno-lang/tree/main/packaging/winget),
which are what Microsoft's collection of packages takes.
[docs/packages.md](https://github.com/partham20/zeno-lang/blob/main/docs/packages.md)
says what each package is, and what is still to be done before
`apt install zeno` and the rest work with one word.

## Download

To do it by hand instead:

| Machine | File |
|---|---|
| Linux, x86-64: most PCs and servers | `zeno-0.1.0-linux-x86_64.tar.gz` |
| Linux, ARM64: a Raspberry Pi 3, 4 or 5 with a 64-bit system, ARM servers | `zeno-0.1.0-linux-arm64.tar.gz` |
| Linux, 32-bit ARMv7: a Raspberry Pi 2 or later with a 32-bit system | `zeno-0.1.0-linux-armv7.tar.gz` |
| Linux, 32-bit ARMv6: a Raspberry Pi 1 or Zero | `zeno-0.1.0-linux-armv6.tar.gz` |
| Linux, 32-bit x86 | `zeno-0.1.0-linux-x86.tar.gz` |
| macOS, Apple silicon | `zeno-0.1.0-macos-arm64.tar.gz` |
| macOS, Intel | `zeno-0.1.0-macos-x86_64.tar.gz` |
| Windows, x86-64 | `zeno-0.1.0-windows-x86_64.zip` |
| Windows, 32-bit x86 | `zeno-0.1.0-windows-x86.zip` |
| Windows, ARM64 | `zeno-0.1.0-windows-arm64.zip` |

Unpack it and put `zeno` (`zeno.exe` on Windows) somewhere on your
`PATH`. It is one file and needs nothing else installed. The folder
also holds the docs, the examples and the editor setup.

```sh
tar -xzf zeno-0.1.0-linux-x86_64.tar.gz
cd zeno-0.1.0-linux-x86_64
./zeno --version
./zeno run examples/hello.zeno
```

On macOS, a program downloaded with a browser is held back because
Apple has not signed it. `xattr -d com.apple.quarantine zeno` lets it
run.

`zeno build` hands the C it writes to a C compiler, so it needs one
(`cc`, or the one `CC` names; on Windows, `set CC=gcc` with MinGW).
`zeno build --llvm` needs clang.
`zeno fetch` needs git. Everything else needs nothing.

## What was checked

Every build but one was run before it was released: it ran all the
examples through the interpreter and the virtual machine, ran their
tests, formatted them and made a new program with `zeno new`. The ARM
builds for Linux ran under an emulator and the Intel build for macOS
under Apple's translation. The Windows build for ARM64 was built and
not run, because there was no machine to run it on.

The whole test suite (more than 450 tests), which also compiles every test
program to C and to LLVM IR and runs the result, passes on Linux
x86-64, on macOS on Apple silicon and on Windows x86-64.

On Windows, `zeno build` was checked on three examples with MinGW's
gcc, and `zeno build --llvm` with the clang that comes with Visual
Studio. Each prints exactly what `zeno run` prints. Compiling with
Microsoft's own C compiler (`cl`) has not been tried.
