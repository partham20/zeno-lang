\chapter{Interfaces}\label{ch-interfaces}

A function that adds up areas should work for circles, for squares,
and for the shape somebody writes next year. A function that sends a
message should work through a serial port, a radio, or a log kept in
memory for testing. An \emph{interface} says what all of them can do,
and each class says that it is one.

\section{Declaring an interface}

An interface is a list of functions with no bodies: what can be asked,
not how it is done.

\begin{zeno}
interface Shape {
    function area(self) -> float
    function scale(self, by: float)
}

class Circle is Shape {
    radius: float

    function area(self) -> float {
        return 3.14159 * self.radius * self.radius
    }

    function scale(self, by: float) {
        self.radius = self.radius * by
    }
}

class Square is Shape {
    side: float

    function area(self) -> float {
        return self.side * self.side
    }

    function scale(self, by: float) {
        self.side = self.side * by
    }
}

function total(shapes: list[Shape]) -> float {
    var sum = 0.0
    for shape in shapes {
        sum += shape.area()
    }
    return sum
}

let shapes: list[Shape] = [Circle(1.0), Square(2.0)]
print(total(shapes))
for shape in shapes {
    shape.scale(2.0)
}
print(total(shapes), shapes)
\end{zeno}

\verb|total| was written once. \verb|shape.area()| runs the
\verb|area| of whatever class the object is, and that is decided while
the program runs. An object seen through an interface still prints as
the class it is.

\section{The rules}

\paragraph{An interface lists functions,} each with \verb|self| first
and a type on every other parameter and on the result. It has no
fields and no bodies.

\paragraph{A class says which interfaces it is,} after \verb|is| on
its first line: \verb|class Box is Named, Sized|. It is not one unless
it says so.

\paragraph{The class has every function of the interface, written the
same way}: the same parameter names, the same types, the same result,
and the same defaults, if the interface has any (below).
It may have more of its own. A missing function, or one written
differently, is reported at the class:

\begin{zeno}[fails=yes]
interface Shape {
    function area(self) -> float
    function scale(self, by: float)
}

class Dot is Shape {
    function area(self) -> float {
        return 0.0
    }
}
\end{zeno}

\begin{zeno}[fails=yes]
interface Shape {
    function scale(self, by: float)
}

class Dot is Shape {
    function scale(self, factor: float) {
    }
}
\end{zeno}

\begin{why}
In Go, and in Python's protocols, any class that happens to have an
\verb|area| and a \verb|scale| is a \verb|Shape| without a word. That
saves a line and costs two things: a class whose \verb|area| means
something else is a \verb|Shape| by accident, and a class meant to be
one, with \verb|scale| misspelt, is found out far away, at some call
that passes it. With \verb|is Shape| the promise is written where the
reader of the class sees it, and it is checked there. (Decision 10.4.)
\end{why}

\section{A default for a parameter}

A parameter of an interface's function can have a default, as a
parameter of any function can (\hyperref[ch-functions]{Functions}).
Each class writes the same default, so a call that leaves it out
means the same through the interface and on the object:

\begin{zeno}[file=motors.zeno, dir=defaults]
interface Motor {
    function spin(self, speed: int = 1000, wait: ms = 5 ms)
}

class Fan is Motor {
    function spin(self, speed: int = 1000, wait: ms = 5 ms) {
        print("fan at", speed, "after", wait)
    }
}

class Pump is Motor {
    function spin(self, speed: int = 1_000, wait: ms = 5 ms) {
        print("pump at", speed, "after", wait)
    }
}

function start(motors: list[Motor]) {
    for motor in motors {
        motor.spin()
        motor.spin(wait=20 ms)
    }
}

start([Fan(), Pump()])
Fan().spin(400)
\end{zeno}

``The same'' is the same value: \verb|1_000| and \verb|1000| are the
same, and so is a case of an enum written bare, \verb|Fast|, and with
its enum's name, \verb|Mode.Fast|. A class that writes
another value, or none, is refused at the class, with both defaults:

\begin{zeno}[fails=yes]
interface Motor {
    function spin(self, speed: int = 1000)
}

class Fan is Motor {
    function spin(self, speed: int = 2000) {
        print("fan at", speed)
    }
}
\end{zeno}

A default in an interface is a plain value: a number, text that is
not an f-string, \verb|true|, \verb|false|, \verb|none|, a quantity
such as \verb|5 ms|, or a case of an enum that carries nothing. A sum
such as \verb|2 * 500|, or a call, is refused where it is written.

Where the interface writes no default, a class may still have one of
its own. A call on the object can leave that argument out, but a call
through the interface must give it, so the two cannot mean different
things without the reader seeing it.

\begin{why}
\verb|motor.spin()| is one line that runs a different class each
time. If each class filled in its own default, the line would mean a
different speed for each motor, and nothing on the line or in the
interface would say so. With one value written in both places, the
interface tells the whole truth. Only a plain value is allowed so that
``the same'' has one meaning, which the reader can check by eye:
\verb|2 * 3| and \verb|6| would need working out. (Decision 58.20.)
\end{why}

\section{Where an interface goes}

An object of a class goes wherever one of its interfaces is wanted: a
variable, a parameter, a result, a field, and each of those with
\verb|or none|.

A list of the class does not go where a list of the interface is
wanted, because whoever held it as a \verb|list[Shape]| could then
append a \verb|Square| to a list of circles:

\begin{zeno}[fails=yes]
interface Shape {
    function area(self) -> float
}
class Circle is Shape {
    radius: float
    function area(self) -> float {
        return 3.0 * self.radius * self.radius
    }
}
function total(shapes: list[Shape]) -> float {
    var sum = 0.0
    for shape in shapes {
        sum += shape.area()
    }
    return sum
}
let circles = [Circle(1.0), Circle(2.0)]
print(total(circles))
\end{zeno}

The message says what to do: say what the list holds where it is
made, by writing \verb|list[Shape]| as the type of \verb|circles|. A list written out in
place, as in \verb|total([Circle(1.0)])|, is a list of whatever the
place wants. (Decision 10.7.)

\section{Through an interface, only its functions}

Through an interface, only the interface's functions can be used. Not
the fields, not the class's other functions, and there is no way back
from the interface to the class:

\begin{zeno}[fails=yes]
interface Shape {
    function area(self) -> float
}
class Circle is Shape {
    radius: float
    function area(self) -> float {
        return 3.0 * self.radius * self.radius
    }
}
let s: Shape = Circle(1.0)
print(s.radius)
\end{zeno}

What else an object has depends on its class, and that is only known
when the program runs. If code needs it, the interface should have a
function for it.

\begin{why}
A way back, such as Java's casts or Rust's \verb|downcast|, lets code
ask "which class are you really?" and do something different for
each, which is what the interface was meant to save. When the classes
are a fixed list known in advance, an enum and \verb|match| say that
directly. (Decision 10.8.)
\end{why}

\section{Errors through an interface}

An interface function can say what it raises. A class may raise less
than the interface says, never more, because whoever calls it through
the interface would not know:

\begin{zeno}
class Full {
    waiting: int
}

interface Port {
    function send(self, text: str) -> int raises Full
    function name(self) -> str
}

class Uart is Port {
    speed: int
    queued: int = 0

    function send(self, text: str) -> int raises Full {
        if self.queued >= 2 {
            raise Full(self.queued)
        }
        self.queued += 1
        return len(text)
    }

    function name(self) -> str {
        return f"uart at {self.speed}"
    }
}

class MemoryLog is Port {
    lines: list[str] = []

    function send(self, text: str) -> int {
        self.lines.append(text)
        return len(text)
    }

    function name(self) -> str {
        return "memory log"
    }
}

function report(port: Port, text: str) {
    try {
        print(port.name(), "sent", port.send(text))
    } except Full as f {
        print(port.name(), "is full with", f.waiting)
    }
}

let ports: list[Port] = [Uart(9600), MemoryLog()]
for turn in range(3) {
    for port in ports {
        report(port, "hello")
    }
}
\end{zeno}

\verb|MemoryLog| never fills up and raises nothing, and that is fine.
A class whose \verb|send| raised something \verb|Port| does not list
would be refused at the class.

\section{Interfaces and owners}

Some lists and objects have one owner, which frees them when it is
done with them: those of an \verb|owned class| in any program, and
every one in a program built with no collector
(\hyperref[ch-ownership]{Ownership},
\hyperref[ch-no-collector]{Building with No Collector}). Two things
about interfaces follow from that.

\paragraph{A function that takes out what its object owns} can stand
for one of an interface. Here \verb|take_last| of a \verb|Stack| takes
a task out of the stack's own list:

\begin{zeno}[file=pile.zeno, dir=owners, cmd=zeno build --no-collector {file} ;; ./pile]
class Task {
    name: str
}

interface Pile {
    function take_last(self) -> Task
    function size(self) -> int
}

class Stack is Pile {
    tasks: list[Task]

    function take_last(self) -> Task {
        return self.tasks.pop()
    }

    function size(self) -> int {
        return len(self.tasks)
    }
}

function drain(pile: take Pile) {
    while pile.size() > 0 {
        print(pile.take_last().name)
    }
}

drain(Stack([Task("wash"), Task("dry")]))
\end{zeno}

A call through the interface is then held to the same rule as a call
on the object: only the owner may make it. \verb|drain| takes the
pile, so it is the owner. A function that was only lent the pile may
not take anything out of it, since whoever lent it may still be using
what is inside:

\begin{zeno}[file=pile.zeno, dir=owners, lines=28-30, cmd=zeno build --no-collector {file}, fails=yes]
class Task {
    name: str
}

interface Pile {
    function take_last(self) -> Task
    function size(self) -> int
}

class Stack is Pile {
    tasks: list[Task]

    function take_last(self) -> Task {
        return self.tasks.pop()
    }

    function size(self) -> int {
        return len(self.tasks)
    }
}

function drain(pile: take Pile) {
    while pile.size() > 0 {
        print(pile.take_last().name)
    }
}

function peek(pile: Pile) -> str {
    return pile.take_last().name
}

drain(Stack([Task("wash"), Task("dry")]))
\end{zeno}

Nothing is written on the interface's function to say so. It takes out
if the function of any class that is the interface does, and the
checker reads the whole program to find out. So one class that takes
out makes every call of \verb|take_last| through a \verb|Pile| a call
for the owner, even for a pile whose class takes nothing: the caller
cannot know which class it has. (Decision 58.21.)

\paragraph{An owned interface} is to an interface what an
\verb|owned class| is to a class: each object that is one has one
owner, with a collector too. Only an \verb|owned class| can be one,
and an \verb|owned class| can only be an owned interface:

\begin{zeno}[file=shapes.zeno, dir=owned]
owned interface Shape {
    function area(self) -> float
}

owned class Circle is Shape {
    radius: float

    function area(self) -> float {
        return 3.0 * self.radius * self.radius
    }
}

var shapes: owned list[Shape] = [Circle(1.0), Circle(2.0)]
let last = shapes.pop()
print(last.area(), len(shapes))
\end{zeno}

A list of them is an \verb|owned list|, a parameter only looks at one
unless it says \verb|take|, and a field that holds one is in an
\verb|owned class|, as for any owned value. An \verb|owned class| that
says it is a plain interface, or a plain class that says it is an
owned one, is refused at the class, and the message says which word
to write.

\begin{why}
With a collector, an object seen through a plain interface is shared:
it can be copied anywhere. An owned object put there would be an owned
thing inside a shared one, and its owner could free it while a copy
was still in use. \verb|owned interface| says on the interface's first
line, where its reader looks, which kind its objects are, with a word
the language already has. Working it out from the classes would let
one new class change every use of the interface. With no collector
every object has one owner already, so there the word is allowed and
says nothing new. (Decision 58.22.)
\end{why}

\section{No parent classes}

There is no inheritance in Zeno: a class cannot be another class, only
interfaces. What two classes share is declared as an interface that
both are (\hyperref[ch-classes]{Classes}).

\begin{why}
Inheriting fields and code brings the questions every language with it
has had to answer: which \verb|area| runs, what the object looks like
in memory, what happens when two parents have the same field. None of
them is needed to write \verb|total|. (Decision 10.4.)
\end{why}

\section{What it costs}

In a compiled program, each object carries a small number saying which
class it is, and a call through an interface is a \verb|switch| on that
number to the class's function. There are no tables of function
pointers, and nothing is looked up by name. (Decision 10.9.)

\begin{summary}
An interface lists functions with no bodies. A class says which
interfaces it is with \verb|class Name is Interface|, and must have
each function written the same way. An object goes where its interface
is wanted, a list of it only where the list was made as one. Through
an interface only its functions are there. A class may raise less than
its interface says, never more. A default on an interface's parameter
is a plain value, and each class writes the same one. A function that
takes out what its object owns can stand for one of an interface, and
a call through it is then for the owner. Each object of an
\verb|owned interface| has one owner.
\end{summary}
