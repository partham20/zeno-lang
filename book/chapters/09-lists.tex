\chapter{Lists}\label{ch-lists}

A \emph{list} holds several values in order. It can grow and shrink,
and each of its items has a position, counted from 0.

\section{Making a list and reading it}

\begin{zeno}
let primes = [2, 3, 5, 7]
print(primes, len(primes), primes[0], primes[3])
print([], [[1, 2], [3]])
\end{zeno}

The type of a list says what its items are: \verb|primes| is a
\verb|list[int]|. Zeno works it out from the items, or you write it,
which you must do for an empty list that has nothing yet to work it
out from:

\begin{zeno}
let names: list[str] = []
let grid: list[list[int]] = [[1, 2], [3, 4]]
print(names, grid[1][0])
\end{zeno}

A position outside the list is an \verb|IndexError|, and so is a
negative one (\hyperref[ch-text]{Text} gives the reason):

\begin{zeno}[fails=yes]
let primes = [2, 3, 5, 7]
print(primes[4])
\end{zeno}

\section{Changing a list}

\begin{zeno}
let xs = [3, 1, 2]
xs.append(4)           # at the end
xs.insert(0, 9)        # at position 0, moving the rest up
print(xs)
xs[1] = 30             # replace the item at position 1
print(xs)
let last = xs.pop()    # take out the last item, and give it
let first = xs.pop(0)  # take out the item at position 0
print(last, first, xs)
xs.clear()             # take out everything
print(xs)
\end{zeno}

All of these change the list itself, which is why \verb|xs| can be a
\verb|let|: the name always means the same list, while what the list
holds changes. \hyperref[ch-values]{Values and Variables} has the rule.

Every item must be of the list's type:

\begin{zeno}[fails=yes]
let xs = [1, 2]
xs.append("three")
\end{zeno}

\section{Every method of a list}

\begin{center}
\begin{tabular}{lP{8.6cm}}
\toprule
Method & Does \\
\midrule
\verb|append(x)| & puts \verb|x| at the end \\
\verb|insert(at, x)| & puts \verb|x| at position \verb|at|, moving the rest up \\
\verb|pop()| & takes out the last item, and gives it \\
\verb|pop(at)| & takes out the item at \verb|at|, and gives it \\
\verb|clear()| & takes out every item \\
\verb|reverse()| & turns the list round, where it is \\
\verb|sort()| & puts numbers or text in order, smallest first, where it is \\
\verb|find(x)| & the position of the first item equal to \verb|x|, or \verb|none| \\
\verb|slice(from, to)| & a new list of the items from \verb|from| up to, not including, \verb|to| \\
\verb|slice(from)| & a new list of the items from \verb|from| to the end \\
\verb|join(sep)| & for a list of text: one text, with \verb|sep| between the items \\
\verb|map(f)| & a new list of \verb|f| of each item \\
\verb|filter(f)| & a new list of the items for which \verb|f| is \verb|true| \\
\verb|reduce(f, start)| & the items folded into one value with \verb|f|, starting from \verb|start| \\
\bottomrule
\end{tabular}
\end{center}

Beside them stand the functions \verb|len(xs)|, \verb|sum(xs)|,
\verb|min(xs)| and \verb|max(xs)|, the operator \verb|x in xs|, and
\verb|+| to join two lists into a new one.

\begin{zeno}
let numbers = [5, 3, 9, 1]
numbers.sort()
print(numbers, numbers.find(9), numbers.find(4), 3 in numbers)
numbers.reverse()
print(numbers, numbers.slice(1, 3), numbers + [0])
print(["pear", "fig", "apple"].join(", "))
print(sum(numbers), min(numbers), max(numbers))
\end{zeno}

\subsection{What there is no method for}

Some methods that other languages have are left out, because Zeno
already says the thing in one short expression:

\begin{center}
\begin{tabular}{ll}
\toprule
In other languages & In Zeno \\
\midrule
\verb|xs.contains(x)| & \verb|x in xs| \\
\verb|sorted(xs)| & \verb|let ys = xs.slice(0)|, then \verb|ys.sort()| \\
\verb|xs.remove(x)| & \verb|xs.find(x)|, then \verb|xs.pop(at)| \\
\verb|xs.extend(ys)| & \verb|xs += ys| \\
\verb|xs[1:3]| & \verb|xs.slice(1, 3)| \\
\bottomrule
\end{tabular}
\end{center}

\begin{why}
A method gets into the library only if most programs in the big
languages use it and Zeno cannot already say it in one short
expression. That keeps one way to write each thing. (Decision 6.1.)
\end{why}

\subsection{sort and reverse change the list}

\verb|sort| and \verb|reverse| work where the list is and give back
nothing. To keep the old order, sort a copy, which \verb|slice(0)|
makes:

\begin{zeno}
let readings = [5, 3, 9, 1]
let in_order = readings.slice(0)
in_order.sort()
print(readings, in_order)
\end{zeno}

\verb|sort| knows how to order numbers and text, which have one order
that nobody has to be told. Anything else it refuses, with the reason:

\begin{zeno}[fails=yes]
let flags = [true, false]
flags.sort()
\end{zeno}

\subsection{sort with a function}

A list of objects has no order of its own. A program says which order
it wants by giving \verb|sort| a function that takes one item and gives
what the item is ordered by, a number or text: its \emph{key}. The
function comes in \hyperref[ch-function-values]{Functions as Values};
here it is written in place:

\begin{zeno}
class Person {
    name: str
    age: int
}

let people = [Person("Ada", 36), Person("Bo", 20), Person("Cy", 36)]
people.sort(function(person: Person) -> int { return person.age })
for person in people {
    print(person.name, person.age)
}
\end{zeno}

The function is called once for each item, before anything moves.
Items with the same key stay in the order they were: Ada was before
Cy, both are 36, and Ada is still first. So sorting by name and then
by age gives people in order of age, and by name within an age. For
biggest first, give the key with a minus, \verb|return 0 - person.age|.

The function is not asked which of two items comes first, as a sort
is in C or JavaScript. A function that takes two items is refused,
with the reason. (Decision 21.1.)

\begin{why}
A new list is new memory, which a program on a small board may not
want to spend, and a method that gives the list back invites
\verb|let ys = xs.sort()|, where it is not clear whether \verb|xs|
changed. \verb|sort| is \emph{heapsort} in every engine: it needs no
second list, never calls itself, and is never slow, which is what
firmware wants. (Decisions 6.5 and 6.6.)
\end{why}

\subsection{find, and taking out by value}

\verb|find| gives a position or \verb|none|. To take out an item by
its value, find it first, and say what happens when it is not there:

\begin{zeno}
let names = ["Ada", "Grace", "Alan"]
let at = names.find("Grace")
if at is not none {
    names.pop(at)
}
print(names)
\end{zeno}

\section{Joining lists}

\verb|+| makes a new list from two, and \verb|+=| adds a list to the
end of a list variable. Both lists must hold the same kind of thing:

\begin{zeno}
var log: list[str] = ["start"]
log += ["read", "write"]
print(log + ["stop"])
\end{zeno}

\begin{zeno}[fails=yes]
let xs = [1, 2]
print(xs + ["a"])
\end{zeno}

\section{Comprehensions}

A \emph{comprehension} builds a new list from another in one line: an
expression for each item, a \verb|for|, and if you like an \verb|if|
that keeps only some items:

\begin{zeno}
let numbers = range(1, 11)
print([n * n for n in numbers])
print([n for n in numbers if n % 3 == 0])
print([word.upper() for word in ["a", "b"]])
\end{zeno}

It reads the way it would be said: "n times n, for each n in numbers".

\section{map, filter and reduce}

The same work can be done by handing a function to a method.
\verb|map| applies it to each item, \verb|filter| keeps the items it
says \verb|true| for, and \verb|reduce| folds the list into one value:

\begin{zeno}
function square(n: int) -> int {
    return n * n
}
function is_even(n: int) -> bool {
    return n % 2 == 0
}
function add(total: int, n: int) -> int {
    return total + n
}

let numbers = [1, 2, 3, 4, 5, 6]
print(numbers.map(square))
print(numbers.filter(is_even))
print(numbers.reduce(add, 0))
print(numbers.filter(is_even).map(square).reduce(add, 0))
\end{zeno}

The last line reads left to right, in the order things happen: take
the numbers, keep the even ones, square them, add them up.

\begin{why}
As methods, \verb|map|, \verb|filter| and \verb|reduce| read left to
right. As plain functions, the same chain is
\verb|reduce(add, map(square, filter(is_even, numbers)))|, which has to
be read from the inside out. (Decision 3.6b.)
\end{why}

A function can also be written in place, with no name.
\hyperref[ch-function-values]{Functions as Values} covers that.

\section{Two names, one list}

A list is not copied when it is given another name, passed to a
function or put in another list. Every name sees the one list:

\begin{zeno}
function add_reading(readings: list[float], r: float) {
    readings.append(r)
}

let mine = [20.5]
let also_mine = mine
add_reading(also_mine, 21.0)
print(mine)
\end{zeno}

When you want a separate list, make one: \verb|xs.slice(0)| copies the
whole list.

\begin{why}
Sharing is what Python, Java and JavaScript programmers expect, and it
is the cheapest thing to do. In an ordinary build a garbage collector
makes it safe; a build with no collector gives each list one owner
instead, and \hyperref[ch-no-collector]{Building with No Collector}
explains how. (Decision 3.10.)
\end{why}

\section{Equal lists}

Two lists are equal when they have equal items in the same order:

\begin{zeno}
print([1, 2] == [1, 2], [1, 2] == [2, 1])
\end{zeno}

\begin{summary}
A list holds values of one type, in order, from position 0. It grows
with \verb|append|, \verb|insert| and \verb|+=|, shrinks with
\verb|pop| and \verb|clear|, and is ordered with \verb|sort| and
\verb|reverse|, all in place. \verb|find|, \verb|slice|, \verb|join|,
\verb|map|, \verb|filter| and \verb|reduce| give new values.
Comprehensions build lists in one line. A list is shared, never copied
without being asked.
\end{summary}
