\chapter{The Board}\label{ch-board}

Zeno is for programs that run on a board: a microcontroller with pins
that drive LEDs and relays, registers that control its peripherals,
and a clock. This chapter is about the \verb|board| module, which is
how a program reaches them, and about the simulated board that lets
the same program run on a computer.

\section{Blink}

The program Zeno was made for, written on the first day, before there
was a compiler, is this:

\begin{zenofrag}[file=blink.zeno]
from board import led
from time import sleep

while true {
    led.toggle()
    sleep(500 ms)
}
\end{zenofrag}

It never ends, as firmware does not. Run on a computer, it prints
\verb|led on|, \verb|led off|, \verb|led on| every half second, until
Ctrl-C stops it. Compiled for a microcontroller, the same lines blink
the LED.

\section{The simulated board}

A computer has no LED on pin 13, so \verb|zeno run| gives the program
a \emph{simulated} board. It has 64 pins, all low to begin with, with
the LED on pin 13, where an Arduino Uno has it. It prints a line each
time a pin \emph{changes} level, which is what a logic analyser
clipped to the pin would show:

\begin{zeno}
from board import led

print(led, led.is_on())
led.on()
led.on()
led.toggle()
print(led.is_on())
\end{zeno}

The second \verb|led.on()| printed nothing, because the pin was
already high and did not move.

\section{Pins}

\verb|led| is the pin the LED is on, and \verb|pin(n)| is the pin with
that number. A pin can do four things:

\begin{center}
\begin{tabular}{ll}
\toprule
Written & Does \\
\midrule
\verb|p.on()|, \verb|p.off()| & drive it high or low \\
\verb|p.toggle()| & give it the other level \\
\verb|p.is_on()| & is it high? A \verb|bool| \\
\verb|p.number| & which pin it is \\
\bottomrule
\end{tabular}
\end{center}

\verb|Pin| is a type, so a function can ask for one, and a pin can go
in a list, a field or a \verb|Pin or none|:

\begin{zeno}
from board import pin
from time import sleep

function flash(light: Pin, times: int) {
    for turn in range(times) {
        light.toggle()
        sleep(10 ms)
    }
}

let lamps = [pin(2), pin(3)]
for lamp in lamps {
    flash(lamp, 2)
}
\end{zeno}

A pin the board does not have is a \verb|ValueError|:

\begin{zeno}[fails=yes]
from board import pin
let relay = pin(99)
\end{zeno}

\begin{why}
A pin is not an \verb|int|: if it were, \verb|on(count)| would
compile, and so would \verb|led + 1|. It is not an object either,
because an object lives in memory from the collector, and blinking an
LED should not need one. A pin is a kind of its own to the checker,
and a plain number in the compiled program, so it costs what an
\verb|int| costs. Units work the same way. (Decision 3.15.)
\end{why}

\section{Inputs}

A button, a switch or a sensor that says yes or no is a pin the
program reads. \verb|input_pin(n)| makes the pin with that number an
input, and gives an \verb|InputPin|:

\begin{center}
\begin{tabular}{ll}
\toprule
Written & Gives \\
\midrule
\verb|input_pin(2, pull_up)| & an input that a pull-up holds high \\
\verb|input_pin(2, pull_down)| & an input that a pull-down holds low \\
\verb|input_pin(2)| & an input that nothing pulls \\
\verb|b.is_high()|, \verb|b.is_low()| & the level the pin is at now \\
\verb|b.number| & which pin it is \\
\bottomrule
\end{tabular}
\end{center}

A button usually joins its pin to ground when it is pressed, and a
pull-up holds the pin high the rest of the time, so a press reads low:

\begin{zeno}
from board import input_pin, pull_up, led

let button = input_pin(2, pull_up)
if button.is_low() {
    led.on()
}
print(button, button.is_high())
\end{zeno}

On a computer nothing presses the button, so a pull-up reads high, a
pull-down low, and a pin nothing pulls keeps the level it had. Making
an input prints nothing: the simulated board prints what the program
drives, and a pull is not driven.

An \verb|InputPin| has no \verb|on| and a \verb|Pin| has no
\verb|is_low|, and each mistake is found before the program runs:

\begin{zeno}[fails=yes]
from board import input_pin, pull_up
let button = input_pin(2, pull_up)
button.on()
\end{zeno}

\begin{why}
An output is driven and an input is read, and a pin is one or the
other, so they are two types and the checker keeps them apart, as
Rust's \verb|embedded-hal| does. An input says \verb|is_high| and
\verb|is_low| and not \verb|is_on|, because with a pull-up a pressed
button is low, and ``on'' would then mean two things. The pull is said
where the pin is made, because that is where the hardware sets it, and
\verb|pull_up| and \verb|pull_down| are values of the \verb|board|
module of the type \verb|Pull|, so a function can take one.
(Decision 45.)
\end{why}

The example \verb|examples/doorbell.zeno| counts presses of a button
and rings a bell for each.

\section{Reading a voltage}

Most of what a board measures arrives as a voltage: a potentiometer,
a thermistor, a battery through two resistors. \verb|analog_pin(n)|
gives an \verb|AnalogPin|, read by the board's converter:

\begin{center}
\begin{tabular}{ll}
\toprule
Written & Gives \\
\midrule
\verb|a.voltage()| & what the pin is at now, in \verb|V| \\
\verb|a.count()| & the same as the converter counted it, an \verb|int| \\
\verb|a.max_count| & the count that stands for the whole reference \\
\verb|a.number| & which pin it is \\
\bottomrule
\end{tabular}
\end{center}

The voltage has its unit, so it is compared with a voltage and
nothing else, and it makes other units
(\hyperref[ch-units]{Numbers with Units}):

\begin{zeno}
from board import analog_pin, pin

let sensor = analog_pin(4)
print(sensor.voltage(), sensor.count())
pin(4).on()
let level = sensor.voltage()
print(level, level.mV, level < 1200 mV)
print(level / 330 ohm, sensor.count() / sensor.max_count)
\end{zeno}

On a computer nothing is wired to the pin: one that is low reads
\verb|0 V|, and one that is high reads the whole reference,
\verb|3.3 V| and a count of 4095, as a voltmeter on it would.

\begin{why}
A bare \verb|512| from a converter means nothing until one knows its
bits and its reference, and those are the board's. So the board says
them once, and \verb|voltage()| hands the program volts, which the
checker then keeps from being compared with a bare number. The count
is there too, with \verb|max_count|, for a share of the scale or a
lookup table. (Decision 47.)
\end{why}

The example \verb|examples/battery.zeno| watches a battery through a
divider and lights the LED when it is low.

\section{A serial port}

A serial port is how a board talks: to a terminal on a computer, to a
GPS module, to a modem. \verb|serial(n, speed)| opens the port with
that number, at a speed in \verb|baud|, and gives a \verb|Serial|:

\begin{center}
\begin{tabular}{ll}
\toprule
Written & Does \\
\midrule
\verb|s.write("hi\n")| & sends the bytes of the text, and no line end of its own \\
\verb|s.write_bytes(frame)| & sends a \verb|list[u8]| as it is \\
\verb|s.read_byte()| & the next byte, waiting for it: a \verb|u8 or none| \\
\verb|s.has_byte()| & has a byte come that has not been read? No waiting \\
\verb|s.number| & which port it is \\
\bottomrule
\end{tabular}
\end{center}

\verb|read_byte| gives \verb|none| only when no byte can come any
more. On a board that is never; on a computer it is the end of what
was typed, because there every serial port is the terminal itself, as
a serial monitor is. A program that must not wait asks
\verb|has_byte| first.

\begin{zeno}[stdin=on\nstatus\n]
from board import serial

let port = serial(1, 115200 baud)
port.write("ready\n")
var byte = port.read_byte()
var line = ""
while byte is not none and byte != 10 {
    line = line + char(byte)
    byte = port.read_byte()
}
port.write(f"got {line}\n")
\end{zeno}

\begin{why}
The speed has a unit for the reason \verb|sleep| has one:
\verb|serial(1, 9600)| does not say which number is the port.
Text and bytes are sent by two methods, as \verb|files.write| and
\verb|files.write_bytes| are, so neither is a guess. Reading a byte
waits, which is what a console or a modem wants, and
\verb|has_byte| is there for a loop that has other work.
(Decision 46.)
\end{why}

The example \verb|examples/console.zeno| is a small command line over
a serial port that drives the LED.

\section{The clock}

\verb|sleep| waits for a time with a unit, and \verb|now()| reads a
clock that only goes forward, in milliseconds, from a moment such as
when the board was switched on (\hyperref[ch-units]{Numbers with
Units}). Only the difference of two readings means anything:

\begin{zeno}
from time import sleep, now

let start = now()
sleep(50 ms)
let took = now() - start
print("took at least 50 ms:", took >= 50 ms)
\end{zeno}

\section{Registers}

A microcontroller's peripherals, its timers, serial ports and
converters, are controlled through \emph{registers}: words of memory
at fixed addresses, given in the data sheet. \verb|register(u32, address)|
 names one, with its size:

\begin{zeno}
from board import register

let control = register(u32, 0x4000_4400)
let data = register(u8, 0x4000_440C)

unsafe {
    control.write(u32(control.read() | 1 << 0))
    data.write(0x41)
    print(control.read(), data.read())
}
\end{zeno}

A value written must fit the register: \verb|control.read() | 1| is an
\verb|int|, as every sum of sized numbers is
(\hyperref[ch-sized-numbers]{Sized Numbers and Bits}), so
\verb|u32(...)| puts it back, with a check.

Reading and writing a register must be inside \verb|unsafe { }|,
because a wrong address or a wrong bit can stop a chip, and Zeno
cannot check either. The block marks the lines a reviewer should read
twice:

\begin{zeno}[fails=yes]
from board import register
let data = register(u8, 0x4000_440C)
data.write(0x41)
\end{zeno}

On the simulated board a register is a word that remembers what was
written, and each write is printed. On a real board it is the real
address. \hyperref[ch-unsafe]{Unsafe Code} is about \verb|unsafe| and
memory by hand.

\section{A real board underneath}

A compiled program meets the hardware in four C functions, and these,
with the number of pins, are everything Zeno knows about a board:

\begin{zenofrag}[lang=shell]
zeno_board_write(pin, level)   drive a pin high or low
zeno_board_read(pin)           is the pin high?
zeno_board_sleep(seconds)      wait
zeno_board_now()               a clock that only goes forward, in ms
\end{zenofrag}

A program that reads a pin needs a fifth,
\verb|zeno_board_input(pin, pull)|, which makes the pin an input with
no pull (0), a pull-up (1) or a pull-down (2). A program with a serial
port needs four more, and \verb|ZENO_SERIALS|, the number of ports:
\verb|zeno_board_serial_open|, \verb|_write|, \verb|_ready| and
\verb|_read|. One that reads a voltage needs
\verb|zeno_board_analog| and \verb|zeno_board_analog_read|, with the
converter's bits and reference. Only a program that uses them calls them, so a header
with four still builds every other program.

The simulated board is these four, written for a computer. For a real
microcontroller they are written once, over the vendor's library, in a
header, and the C compiler is told where it is.
\hyperref[ch-firmware]{Firmware} shows how, with a sketch for an
STM32. The Zeno program does not change by a line.

\begin{why}
Four functions is the smallest surface a port can have: a board is
working the day those four are. The checks, such as a pin that does
not exist or a wait below zero, are done once above them, for every
board, so the four can be four lines each. (Decision 5.12.)
\end{why}

\section{What the board does not have yet}

A button can be read, but nothing waits for it: a program looks at the
pin as often as it needs to. On a computer nothing can press it yet.
Nor can a voltage be fed to a pin there. Interrupts, timers and PWM
are not in the \verb|board| module yet. Until they are, a program reaches them
through their registers, at the addresses the data sheet gives.
\hyperref[app-limits]{Appendix G} lists these.

\begin{summary}
\verb|from board import led, pin, register|. A pin is driven with
\verb|on|, \verb|off| and \verb|toggle| and asked with \verb|is_on|;
\verb|Pin| is a type. \verb|input_pin(n, pull_up)| gives an
\verb|InputPin|, read with \verb|is_high| and \verb|is_low|.
\verb|analog_pin(n)| gives an \verb|AnalogPin|, whose \verb|voltage()|
is in volts. \verb|serial(n, 115200 baud)| gives a \verb|Serial|, which
writes text and bytes and reads a byte at a time. \verb|sleep| and \verb|now| keep time with units.
A register is read and written inside \verb|unsafe|. \verb|zeno run|
simulates the board and prints each change; a compiled program sits on
four C functions that a real board provides.
\end{summary}

\begin{enumerate}
\item Blink the LED in Morse code: \verb|SOS|, with dots of 100 ms.
\item Write a class \verb|Relay| with a pin and a name, and methods
  \verb|close| and \verb|open| that print what they do.
\item Change the traffic light so that green lasts twice as long as
  red, and add a pedestrian lamp on pin 5.
\item Write a register without \verb|unsafe| and read the message.
\item Change the doorbell to ring twice for a press that lasts longer
  than half a second.
\end{enumerate}
\end{tryit}
